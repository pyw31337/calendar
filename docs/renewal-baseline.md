## 2. 화면별 뷰포트 스크린샷 (로컬, 390/430/768/1024/1440px)

로컬 빌드를 로컬 정적 서버로 띄우고 `?id=kkot`로 진입해 캡처했다. **주의:** 이 실행 환경은 외부 네트워크(Firebase)가 차단되어 있어 캘린더가 "Firebase에서 실시간 캘린더 데이터를 불러오는 중" 상태로 멈춰 있다 — 이는 실제 라이브 버그가 아니라 이 세션 특유의 네트워크 제약이다. 셸(헤더/탭/캘린더 그리드 뼈대) 구조 확인용으로만 사용한다. 실제 라이브 확인은 WP-12(통합/배포) 단계에서 별도로 수행한다.

- 390px: 헤더(브랜드명 + 검색 + 햄버거 메뉴) → 상단 4탭(투표/채팅/정산/메모, 정산에 카운트 배지) → 월간 캘린더 카드 → 채팅 미리보기(입력창 포함)가 세로로 이어지는 단일 페이지 구조.
- 1440px: 같은 구조가 폭만 넓어진 형태로 유지된다 (레이아웃 자체는 반응형이지만 정보 구조는 동일) — 1.2절에서 지적한 "긴 단일 페이지"가 데스크톱에서도 동일하게 재현됨을 확인.
- 스크린샷 파일은 세션 스크래치 디렉터리에 저장했으며 저장소에는 커밋하지 않는다 (바이너리 스냅샷은 별도 시각 회귀 도구 도입 시 재검토).

## 5. 현재 정보 구조 (실측)

`src/ui/ui-side-menu.js` 기준 실제 내비게이션 구성:

- 상단 4탭: 투표 / 채팅 / 정산(카운트 배지) / 메모
- 사이드 메뉴(햄버거) Group 2: 채팅 / 정산 / 갤러리 / 장소 / 메모
- 사이드 메뉴 Group 3+4: 공유하기 / 설정
- 헤더: 브랜드/캘린더 전환, 검색, 햄버거 메뉴

즉 현재는 "저장 출처별" 메뉴(채팅/메모/갤러리/장소)가 두 군데(상단 탭 + 사이드 메뉴)에 중복 존재하며, 마스터플랜 4.1의 목표 하단 탭(캘린더/대화/기록/정산/더보기) 구조와는 다르다 — WP-01에서 다룰 격차.
