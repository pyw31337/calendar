# V2 완료 후 품질·안정화 실행 로드맵

이 문서는 V2 디자인 작업이 끝난 뒤 이어서 진행할 품질 개선 항목을 정리한 실행 문서다.
다른 에이전트가 작업하더라도 기존 사진·댓글·태그 계약과 캘린더 격리를 보존해야 한다.

## 실행 원칙

- 하나의 항목은 하나의 작은 PR로 구현한다.
- 데이터 삭제·Storage 이동·태그 일괄 정리는 하지 않는다.
- 변경 전 `cw`, `jhair`, `kkot`의 읽기 전용 수량을 기록한다.
- 각 PR은 lint → 단위 테스트 → build → 브라우저 스모크 → 라이브 확인 순서로 진행한다.
- 외부 링크 미디어는 원본을 자동 복제하지 않으며, 권리 확인이 된 경우에만 별도 보관 기능을 제공한다.

## P0 — 데이터 신뢰성과 회귀 방지

### 1. 외부 미디어 만료 fallback 강화

- 대상: 채팅 말풍선, 메모, 검색 결과의 외부 이미지·영상
- 목표: 로드/재생 실패를 감지해 원본 출처 링크와 명확한 안내를 제공
- 완료 조건: 404/403/네트워크 실패에서 콘솔 예외 없이 fallback 표시, 재시도 버튼 제공
- 금지: 제3자 미디어를 사용자 동의 없이 서버에 복제

### 2. 사진 인덱스 건강 점검 도구

- 대상: `photoIndex`, `meetingPhotoIndex`, 원본 메시지/메모
- 목표: 캘린더별 총량·누락·중복·삭제표시 불일치를 읽기 전용으로 보고
- 완료 조건: `cw·jhair·kkot`에 대해 원본과 인덱스 수량 비교 리포트 생성
- 적용 작업은 dry-run 결과를 검토한 후 별도 승인으로 수행

### 3. 댓글·태그 저장 회귀 테스트

- 시나리오: 저장 → 즉시 재조회 → 라이트박스 닫기/재오픈 → 강력 새로고침
- 검증: 사진별 댓글·태그 독립성, 부분 denorm이 풍부한 원본을 덮어쓰지 않음
- 대표 fixture: 다중 이미지 메시지, 한글 태그, 동일 날짜의 여러 사진

## P1 — 실시간 상태와 성능

### 4. 타이핑 presence 보호

- 세션당 heartbeat·idle 쓰기 상한과 만료 문서 정리 상한을 유지
- 동일 참여자의 중복 탭을 dedupe
- 권한 오류 시 채팅 기능 전체를 막지 않고 표시만 graceful degradation

### 5. 라이브 스모크 확대

- 배포 후 각 캘린더의 사진 수·댓글 수·태그 표시·콘솔 오류를 자동 확인
- 최소 경로: 갤러리 전체/일자별, 추억, 인물, 일정 사진 탭, 라이트박스 재오픈
- 실패 시 배포 성공으로 표시하지 않고 원인 로그를 보존

### 6. 이미지·영상 로딩 성능 측정

- 저사양 CPU·3G 조건에서 썸네일 우선, 원본 지연 로드, 페이지네이션 동작 측정
- 목표: 초기 상호작용 가능 시점과 스크롤 프레임 저하를 기준선과 비교
- 원본 URL은 상세 진입 전 요청하지 않음

## P2 — 선택적 보관과 운영성

### 7. 권리 확인형 미디어 미러링

- 사용자가 직접 업로드했거나 권리를 확인한 파일만 Firebase Storage에 보관
- 외부 URL, 보관 상태, 실패 사유를 별도 필드로 관리
- 기본값은 미러링하지 않음; 사용자 명시 동의와 용량 제한 필수

### 8. 관측성·알림

- 인덱스 누락, 댓글 0 오표시, 미디어 fallback 발생을 개인정보 없이 집계
- 오류율·지연시간·재시도율을 캘린더별로 분리
- 사용자 콘텐츠 본문·사진·댓글은 로그에 기록하지 않음
