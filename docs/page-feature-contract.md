# 페이지·기능 계약 및 실데이터 검증 기준

이 문서는 각 화면이 어떤 데이터를 소유하고 어떤 결과를 보여야 하는지 고정한다. 테스트는 `test_` 또는 `stress_`로 시작하는 격리 캘린더에서만 쓰기를 수행하며, 운영 캘린더(`kkot`, `cw`, `jhair`)는 읽기 전용으로 확인한다.

## 공통 계약

- 모든 데이터 경로는 `calendars/cal_<calendarId>` 아래로 격리한다.
- 생성·수정·삭제 후 실시간 화면, 새로고침, 새 브라우저 세션에서 같은 결과가 보여야 한다.
- 채팅·갤러리·일정에서 올라온 사진은 하나의 전역 자산으로 취급하지만 댓글은 사진 자산 하나당 정확히 하나의 독립 스레드를 가진다.
- 로딩, 빈 상태, 오류 상태를 실제 데이터 없음과 혼동하지 않는다.
- 실패한 쓰기는 성공처럼 표시하지 않으며 재시도하더라도 같은 작업이 중복 생성되지 않아야 한다.

## 화면별 계약

| 페이지 | 원본 데이터 | 필수 입출력 | 교차 화면 불변조건 |
| --- | --- | --- | --- |
| 캘린더/메인 | 캘린더 본문, 기념일, 확정 일정 | 참여자·가능일·메모·투표·기념일 생성/수정/삭제 | 최신 채팅 3개는 사진 업로드 문서에 밀리지 않는다 |
| 채팅 | `messages` | 텍스트·답글·링크·사진 메시지 생성/수정/삭제, 과거 내역 추가 로드 | `uploadSource=gallery/meeting` 문서는 채팅 대화로 세지 않지만 갤러리에는 보인다 |
| 갤러리 | 채팅·갤러리 업로드, 메모, 일정에서 등록된 모든 사진과 링크 | 사진·링크 등록, 태그·댓글·교체·삭제, 전체 이력 탐색 | 실제 자산 수와 총계가 같고, 동일 사진은 한 번만 표시되며 댓글·뱃지는 정확한 사진에만 붙는다 |
| 장소 | `places` | 장소·분류·주소·좌표·메모 생성/수정/삭제 | 일정에 연결된 장소가 다른 캘린더와 섞이지 않는다 |
| 메모 | `memos` | 제목·본문·태그·사진·댓글·고정 생성/수정/삭제 | 날짜/인물 태그 검색과 갤러리 사진이 같은 메모를 가리킨다 |
| 정산 | 확정 일정 및 캘린더 정산 카드 | 지출·수입·개인지출·참여자 행 생성/수정/삭제 | 합계와 개인별 잔액은 새로고침 후에도 동일하다 |
| 보관함/추억 | 기념일과 해당 일정에 명시적으로 등록된 사진 | 기념일 단위 사진 취합, 숨김/복원 | 단순히 같은 날 업로드된 무관한 사진은 섞지 않고, 일정 사진의 추가·삭제가 그대로 반영된다 |
| 콘텐츠 | `customCultureItems`, 기념일/메모 연결 | 사용자 콘텐츠 생성/수정/삭제 및 캘린더·메모 연결 | 콘텐츠를 숨겨도 원본 일정/메모를 임의 삭제하지 않는다 |
| 검색/공유/설정 | 위 컬렉션의 파생 조회 | 전역 검색, 딥링크, 캘린더 전환, 공유 URL | 검색 결과와 딥링크가 정확한 캘린더·원본 항목으로 이동한다 |

## 사진·댓글 불변조건

- 갤러리 총계는 `photoIndex`의 실제 자산 행 수이며 한 페이지는 최대 100장이다.
- 일정 사진은 REST 앨범·`meetingPhotoIndex`·실시간 일정 문서의 합집합이지만 정규화된 자산 URL당 한 장만 보인다.
- 추억 사진은 `meetingDate`, 명시적 날짜 태그, 또는 기념일 자체의 사진으로 그 일정에 연결된 경우만 포함한다. 업로드 시각만 같은 사진은 포함하지 않는다.
- 댓글 문서의 새 키는 정규화된 자산 키다. 구형 키는 한 자산에만 안전하게 대응할 때 읽기 별칭으로만 사용한다.
- 모든 사진 썸네일은 같은 댓글 수 계산과 같은 뱃지 컴포넌트를 사용한다. 뱃지는 검정 반투명 배경과 흰색 숫자이며 0이면 렌더하지 않는다.

## 필수 실데이터 시나리오

각 데이터 유형은 `생성 → 즉시 조회 → 수정 → 실시간 반영 → 새로고침 → 삭제 → 삭제 확인`을 통과해야 한다. 추가로 다음을 반복 검증한다.

1. 서로 다른 두 테스트 캘린더 간 데이터 0건 교차 노출.
2. 채팅/갤러리/일정 업로드 사진을 섞은 뒤 갤러리 합계와 원본 자산 수 일치.
3. 서로 다른 사진에 서로 다른 댓글을 저장한 뒤 뱃지·본문·탐색 순서 일치.
4. 동시 쓰기, 오래된 수정 응답, 재시도에서 데이터 유실·중복 없음.
5. 390px 모바일과 데스크톱에서 입력창, 모달, 키보드, 스크롤 영역이 화면을 벗어나지 않음.
6. Chromium, Firefox, WebKit에서 처리되지 않은 예외, 동일 출처 404, 조치 대상 경고 0건.
7. 테스트 종료 시 생성한 부모 문서와 모든 하위 컬렉션을 재귀 삭제하고 잔존 0건 확인.
