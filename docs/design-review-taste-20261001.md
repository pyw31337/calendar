## 구조(정보 구조)

- **진입점 중복**: 검색이 상단 헤더, 사이드 메뉴 "통합검색", 더보기 페이지에 각각 있다. 설정·공유도 사이드 메뉴 하단과
  더보기 양쪽에 있다. 모바일 하단 "더보기"는 사이드 메뉴를 열고, `?tab=more` 페이지는 링크로만 들어갈 수 있다.
  → 더보기 페이지를 사이드 메뉴와 같은 목록으로 통일하거나, 하단 "더보기"가 이 페이지를 열도록 하나로 정리할 것.
- **갤러리·장소의 위치**: 모바일 하단 바는 정산·메모·캘린더·채팅·더보기다. 매일 쓰는 갤러리는 사이드 메뉴 안에
  있다. 사용 빈도를 보고 정산과 갤러리 자리를 바꿀지 검토(운영 오류 로그 화면별 진입 수로 판단 가능).
- **CSS 구조 부채**: V2 CSS 17,030줄, `!important` 4,856개, 같은 요소를 파일마다 덮어쓰는 "late" 파일이 커지는 구조.
  디자인을 바꿀 때마다 회귀가 생기는 주원인이다. 화면 단위로 토큰을 정리하고 덮어쓰기 규칙을 줄이는 리팩터를
  디자인 변경과 분리된 작업으로 진행할 것(이번 컬러 테마 작업에서 쓴 "fallback 토큰 + 픽셀 비교" 방식이 안전망).

## 진행 원칙

1~4번과 7번은 "덜어내기"라 사용자의 "clean" 메모와 방향이 같고, 기존 화면 구성을 바꾸지 않는다. 5·6번과 구조 정리는
화면 인상이 바뀌므로 시안을 먼저 보여 주고 고른다. 각 단계는 기본 테마 픽셀 비교 + 전 화면 스윕으로 검증한다.
