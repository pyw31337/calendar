# AI 운영 인박스와 태그 판단 정책

## 목적

공유 캘린더 운영자가 처리해야 할 다음 작업을 실제 일정·장소·참석·정산·사진 데이터에서
찾는다. 현재 구현은 macOS Vision/OCR, 기존 태그 분류와 근거 기반 규칙이다.
외부 생성형 모델이나 대화형 자율 에이전트가 구현된 것은 아니다.

홈의 **운영 우선순위**는 다음만 제안한다.

- 21일 이내 확정 일정에 연결된 장소가 없는 경우
- 14일 이내 일정에서 참여자의 참석 여부가 비어 있는 경우
- 지난 60일 이내의 공동 지출 중 어떤 정산 카드에도 포함되지 않은 항목이 있는 경우
- 로컬 사진 분석이 실패했거나, 분석 기기의 생존 신호가 26시간 이상 오래된 경우
- 근거별 검토가 필요한 사진 추천이나 자동 위치 보완 실패가 있는 경우
- 한 지출 항목이 여러 정산 카드에 중복으로 포함된 경우

홈에는 우선 3개와 전체 펼치기를, 서버에는 우선 6개를 보여 주며 날짜·지출 항목·분석 상태라는
근거를 함께 유지한다. 규칙은 [src/core/ai-operations.js](/Users/pyw31337/Developer/calendar/src/core/ai-operations.js)에,
동일한 서버 브리핑용 판단은 [functions/ai-operations.js](/Users/pyw31337/Developer/calendar/functions/ai-operations.js)에 있다.

## 기존 태그를 먼저 확인

`src/core/photo-tag-identity.js`를 AI 검토·보관함·추천·로컬 워커에서 공통으로 사용한다.

- 참여자 이름, 성을 제외한 2글자 이름, 명시적 별칭, 커스텀 인물 태그를 확인한다.
- 장소 이름과 별칭, 띄어쓰기·기호 차이, 과거 24/30자 장소 태그를 확인한다.
- `경기도`, `광명시`, `경기도광명시` 같은 알려진 행정구역은 장소 등록 없이도 인식한다.
- `personTags`, `placeTags`, `locationTags`와 캡션의 기존 태그를 함께 확인한다.
- 같은 의미의 태그는 다시 추천하지 않는다. 6자리/8자리 날짜도 비교한다.
- `인물아님`, `장소아님`은 사용자 제외 의도로 보존한다.
- 무제한 부분일치는 하지 않는다. `영우동`은 `영우`, `서울랜드마크`는 `서울랜드`가 아니다.

원본 인덱스를 아직 읽지 못한 상태는 **확인 중**이다. 빈 데이터로 누락을 확정하지 않는다.
인식한 태그를 화면에 근거로 보여 주며 기존 태그가 충분하면 분류 완료로 처리한다.
기존 사진을 전체 재분석하거나 태그를 일괄 재작성할 필요가 없다.

## 근거와 추정의 분리

- 제안은 데이터를 변경하지 않고, 메시지도 대신 보내지 않는다.
- v5 결과는 태그마다 `tagEvidence`를 저장한다. 기존 태그는 분류에 사용하되 새 추천에서 제외한다.
- 실제 촬영 메타데이터 날짜만 직접 근거로 인정한다. 업로드 시각은 촬영일이 아니다.
- OCR 이름은 사진 속 인물이라는 증거가 아니다. 가까운 등록 장소, 일정 제목, 장면 라벨은
  사람이 검토한다. 가까운 장소가 여러 개면 추정하지 않는다.
- 장면의 최대 점수(예: 0.86)를 인물·장소의 정확도나 일괄 적용 기준으로 사용하지 않는다.
  직접 근거가 모두 있는 새 태그만 원본 변경 여부 재확인 후 명시적 일괄 적용을 허용한다.
- 학습 피드백은 현재 장면 후보만 보강한다. 사람·장소·날짜를 새로 추론하지 않는다.
- 태그 저장 성공 후 검토 기록을 저장한다. 실패를 완료로 표시하지 않고 재시도를 허용한다.
- 수정 화면은 과거 검토 태그를 복원하지 않는다. 명시적인 삭제를 유지하고, 수정 중 다른
  기기의 태그 변경이나 저장 한도 초과를 발견하면 덮어쓰지 않고 중단한다.
- 검토 완료 사진도 다시 수정할 수 있다. 저장 후 원본 태그 캐시를 갱신하며, 캘린더를
  바꾸면 대기 중인 적용과 이전 화면의 결과 표시를 중단한다. 이미 전송한 저장의 감사
  기록은 원래 캘린더에만 남긴다.
- 사진 원본은 로컬 macOS Vision/OCR 파이프라인에서 분석한다. 서버에는 제한된 추천 태그,
  신뢰도, 오류 상태만 저장한다. 얼굴 원본·crop·embedding은 업로드하지 않는다.
- 브리핑은 명시적 작업뿐 아니라 실패·기기 상태를 포함하되, 정상일 때 “무엇인가 해야
  한다”는 잡음을 만들지 않는다.

## 운영 흐름

1. 홈은 먼저 일정과 정산 데이터만 즉시 계산한다.
2. 900ms 뒤 최대 80개의 분석 요약과 최대 10개의 워커 상태를 읽는다. 60초 캐시와 요청
   제한 시간을 사용하고 다른 캘린더의 늦은 응답을 버린다. 표시 수치는 전체 사진 통계가 아니다.
3. 사진 관련 작업은 갤러리의 **AI 분석** 탭으로 직접 연결되며, 열린 화면에서 사람이
   근거와 원본을 확인하고 적용·수정·제외한다.
4. 평일 오전 서버 브리핑은 같은 근거를 사용해 “추천 개수” 대신 캘린더별 다음 작업을
   적고, Firestore 감사 문서에 `operationCount`와 작업 목록을 남긴다.
5. 서버는 최신 하위 컬렉션을 제한적으로 조회한다. 과거 일정과 정산 항목을 병합하고,
   일부 조회 실패는 미확인으로 표시한다. 빈 참석 여부는 불참으로 판단하지 않는다.

## 자동 GPS 보완과 배포

기존 신규 업로드 GPS 처리와 별도로 v5 분석의 위치 보완용
`completeMediaAnalysisLocationTags` 서버 트리거를 추가했다. 이 복구 경로는 기본 비활성이다.
배포 후 캘린더별 `calendar.aiSettings.autoLocationTags: true`와
`autoLocationTagsSince`(활성화 시각, epoch milliseconds)를 명시적으로 설정해야 한다.

- 활성화 이후 업로드·원본 생성 시각이 확인되는 사진만 처리한다.
- 생성 후 편집된 원본, 기존 사진, 사용자 검토 이력, 불완전한 소유 정보는 자동 변경하지 않는다.
- 인덱스와 실제 원본의 GPS가 일치해야 한다. 역지오코딩의 행정구역만 추가하고 모델 추천은 쓰지 않는다.
- 모든 소유 문서와 감사 기록을 단일 트랜잭션으로 반영한다. 태그 한도에 도달하면 전부 보류한다.
- GPS 서명과 처리 이력으로 중복 이벤트·재분석이 사용자가 지운 태그를 복원하지 못하게 한다.
- 외부 조회 실패는 최대 3회로 제한하며, `autoLocationTags: false`로 중단할 수 있다.

클라이언트·Functions 배포와 로컬 워커 재시작은 별도 절차다. 이 코드 수정만으로 배포되지는
않는다. 서버에는 기존 `KAKAO_REST_API_KEY` 시크릿 연결이 필요하다. 오래된 사진의 대량 보완은
별도 확인 없는 자동 작업이 아니다.

## 검증 범위

태그·별칭·메타데이터·사용자 제외·오인식·저장 실패의 합성 회귀 사례를 테스트한다.
`functions/test/media-auto-tags.contract.cjs`는 로컬 테스트 더블과 실제 Firestore 에뮬레이터
양쪽에서 트랜잭션/재시도/사용자 수정 보존을 검증한다.

로컬 Vite 서버에서 `node scripts/ai-operations-browser-smoke.mjs`로 외부 요청을 모킹하고
실제 컴포넌트의 로딩·실패·재시도·이동·모바일 폭·캘린더 격리를 확인한다.
`CALENDAR_SMOKE_BROWSER=firefox` 또는 `webkit`으로 엔진을 변경할 수 있다.
이 테스트는 실제 가족 사진의 얼굴 인식 정확도나 iPhone 실기기 검증을 대신하지 않는다.

로컬 빌드 미리보기(`http://127.0.0.1:4189`)에서
`node scripts/ai-gallery-browser-smoke.mjs`는 실제 갤러리 화면의 기존 태그 인식·재수정·삭제·저장·재열기를
가상 데이터로 확인한다. 서버 명령도 가로채므로 운영 데이터는 읽거나 변경하지 않는다.
주소는 `AI_GALLERY_SMOKE_URL`, 브라우저는 `CALENDAR_SMOKE_BROWSER`로 지정한다.

## 생성형 모델을 추가할 때

현재 서비스에는 외부 생성형 모델의 API 키나 사용자 동의 흐름이 설정되어 있지 않다.
따라서 이 인박스는 먼저 재현 가능한 로컬 Vision/OCR와 결정적 규칙으로 동작한다. 외부
LLM을 추가하려면 다음 조건을 먼저 충족해야 한다.

1. 캘린더별 opt-in과 전송 범위(제목만/본문 포함/사진 제외)를 명시한다.
2. 키는 Secret Manager에만 보관하고, 브라우저에는 절대 노출하지 않는다.
3. 입력을 최소화·가명화하고, JSON 스키마 출력만 허용한다.
4. 모델 결과는 `draft`로만 저장하고, 사용자의 확인 없이 메시지·일정·정산을 수정하지 않는다.
5. 요청당 비용·토큰 상한, 감사 로그, 실패 시 규칙 기반 폴백과 회귀 평가 세트를 둔다.

이 조건 없이 “요약해 주는 AI”를 붙이면 정확성·비용·개인정보 측면에서 운영 편의보다
손해가 커질 수 있다.
