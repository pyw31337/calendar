# Firebase 비용·보안 운영 가드레일

## 적용 완료

- 공개 프록시 함수는 15초 타임아웃, 256MB 메모리, 인스턴스 20개 상한을 사용한다.
- 링크 미리보기는 렌더링 중 네트워크 요청을 만들지 않고, 명시적인 생성·수정 경로에서만 수집한다.
- 공개 URL 프록시는 HTTP/HTTPS만 허용하고 내부·사설·메타데이터 주소를 차단한다.
- 푸시 fan-out은 한 번의 트리거에서 최대 500개 구독만 처리한다.
- Firebase Functions 런타임 의존성을 최신 호환 버전(`firebase-functions` 7.x, `firebase-admin` 14.x)으로 갱신했다.

## 월별 비용 예산 설정

Google Cloud Console에서 `Billing → Budgets & alerts`로 이동해 프로젝트 `metro-live-2918e`에 다음 예산을 만든다.

1. 월 예산: ₩10,000 (현재 사용량과 팀의 허용 한도에 맞춰 조정)
2. 알림 기준: 50%, 75%, 90%, 100%
3. 이메일 수신자: 결제 계정 관리자와 서비스 운영자
4. 예측 알림: 활성화

예산 알림은 비용을 자동 차단하지 않으므로, 90% 알림 발생 시 Billing Report에서 SKU별 Firestore 읽기·Functions 호출량을 확인한다.

## App Check 단계적 적용

1. Firebase Console에서 웹 App Check에 reCAPTCHA Enterprise 또는 reCAPTCHA v3 사이트 키를 등록한다.
2. 프론트엔드에 App Check 초기화를 추가하고 24~48시간 `측정항목만` 모드로 유효 토큰 비율과 구형 클라이언트 오류를 관찰한다.
3. 충분한 토큰 커버리지를 확인한 뒤 Firestore와 Storage부터 enforcement를 켠다.
4. 게스트도 사용하는 공개 HTTP 프록시는 먼저 토큰 누락 비율을 확인하고, 차단 전용 별도 엔드포인트로 단계적으로 전환한다.

사이트 키 등록과 enforcement 전환은 기존 설치형·구형 브라우저를 차단할 수 있으므로 콘솔에서 운영자가 승인한 뒤 진행한다.

## 리전 이전 절차

현재 Firestore 트리거는 `us-central1` 함수가 `asia-northeast3` 리전 데이터에 반응한다. 기존 함수를 바로 이전하면 새 함수 생성과 기존 함수 삭제가 함께 발생할 수 있다.

- 새 리전 함수명을 별도로 배포하고 중복 이벤트·멱등성을 검증한다.
- 24시간 로그와 비용을 관찰한다.
- 트리거 중복이 없음을 확인한 뒤 기존 함수를 별도 릴리스에서 제거한다.

따라서 이번 릴리스에서는 리전 변경을 실행하지 않았으며, 데이터 손실 없는 별도 마이그레이션으로 취급한다.
