## What Was Found Today

- A real Firebase live stress test reproduced save failures under heavy concurrent writes.
- Root cause: Firestore correctly rejects stale base versions with `FAILED_PRECONDITION`, but the REST fallback retry budget/backoff was too small for 8 simultaneous users repeatedly saving the same calendar document.
- Cross-calendar interference was not observed. The problem was within one busy calendar document under high write contention.

## Local Fixes Ready To Commit

- `index.html`
  - Added retryable Firestore conflict detection for `FAILED_PRECONDITION`, stored/base version mismatch, `ABORTED`, and `409`.
  - Increased default save retry budget to 18 attempts.
  - Added exponential backoff with jitter for REST fallback retries.
  - Updated user save and admin create calls to use the larger retry budget.
  - Hid internal test calendars with IDs starting `stress_` or `test_` from the admin dashboard list.

- `scripts/firebase-live-stress-tests.mjs`
  - New production-like Firestore stress test.
  - Creates two isolated test calendars at the same time.
  - For each calendar, simulates 8 participants doing create/update/delete operations.
  - Verifies final active participant count, active availability count, tombstone behavior, note sanitization, and document ID isolation.

- `package.json`
  - Added `npm run stress:firebase`.
